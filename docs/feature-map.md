# SubstanceCraft Feature Map

This is the product capability map derived from the supplied Painter feature inventory. It is a clean-room implementation plan, not a claim of parity. Status is conservative: **Partial** means a tested slice or relevant foundation exists but the acceptance target is incomplete; **Planned** means no implementation of the target exists yet.

## Status key

- **Implemented:** the acceptance target is met and covered by automated tests. A capability area is Implemented once nothing in its row remains open.
- **Partial:** some acceptance criteria are met, or a tested foundation exists, but meaningful work remains.
- **Planned:** no implementation of the acceptance target exists yet.

## Category taxonomy

Every row below (capability area or backlog item) belongs to one of five categories, and every table carries a **Notes** column with practical context (primary implementation crate, dependencies, or the main follow-up risk) that is not restated in the acceptance target:

| Category | Purpose | Examples |
| --- | --- | --- |
| **Features** | What SubstanceCraft can do | Painting, layers, baking, UDIMs |
| **QoL Features** | Make existing workflows faster or easier | Solo mode, layer search, lazy-mouse stabilization |
| **Production Features** | Make it dependable in professional pipelines | Batch jobs, autosave/recovery, asset relinking, caching |
| **Performance Features** | Make the same workflows faster or larger | GPU baking, tiled processing, incremental recomposition |
| **Accessibility Features** | Make the application adaptable to more users | UI scaling, configurable input, colour-vision modes |

## Features (capability areas)

| # | Area | Status | Initial acceptance target | Notes |
| --- | --- | --- | --- | --- |
| 01 | Project and document management | Partial | Versioned JSON project model, validation, atomic `.sproject` save/load, texture sets, named poses, bitmap resource references, and custom export presets are implemented, and the desktop app opens a `.sproject` passed as its first argument. Saves are stable, sorted, diff-friendly JSON (PROD-05); older schemas upgrade on load with a report (PROD-03); autosave and crash recovery (PROD-01) and relinking of moved files (PROD-02) are in place; named inspection cameras are saved with the project (QoL-14). Mesh and bitmap assets remain external references; templates and mesh replacement remain open. | Schema and (de)serialization live in `crates/core`; the on-disk format and migration chain live in `crates/api/src/project_format.rs`, so each schema bump adds one upgrade step there. |
| 02 | Mesh importing and preparation | Partial | Binary FBX 7.4+ and glTF 2.0 (`.gltf` with external or embedded buffers, and `.glb`) static meshes import through the API and desktop picker, with native UVs or planar fallback. glTF flattens the default scene with node transforms applied and maps each material to a material slot. Auto-smoothed shading normals (angle threshold, welded across unshared FBX corners) and crease-aware Loop subdivision (0–3 levels, UV seams preserved) are implemented; ASCII FBX, FBX material slots, and skeletal animation remain open. | FBX/glTF parsing and normal/subdivision math live in `crates/core`; ASCII FBX support would need a separate parser path alongside the existing binary reader. |
| 03 | Texture Sets | Implemented | Multi-material meshes get one texture set per material slot, each with its own layers, channels, and resolution (512 / 1K / 2K / 4K / 8K in the texture-set properties); unselected sets bake in the background so every slot shows its own material in the viewport. A set can remember its own export preset, file format, and UDIM choice ("This set" in the export panel), which "All sets…" and the command line follow unless told otherwise. Sets above 2048² bake in tiles (PERF-03); the viewport shows sets above 4K as a downscaled preview, while exports keep full size. | Background baking runs on a worker thread keyed by texture-set id. The preview copy scales stroke radii with the resolution (`TextureSet::downscaled`), so it looks like the full set filtered down. |
| 04 | Material channels | Partial | Base Color (RGBA); Roughness, Metallic, Height, and Opacity (scalar); Emissive (sRGB); Normal (tangent-space vector); and baked Ambient Occlusion composite per layer with per-layer channel enablement and export. Height converts to normal detail (whiteout blend) with a per-texture-set strength; user-defined channels remain open. | Channel enum and compositing live in `crates/core`; user-defined channels would require extending the fixed `MaterialChannel` enum to a dynamic channel list across bake, export, and UI code. |
| 05 | Painting tools | Partial | Multi-channel paint, erase, grayscale-mask, and ID-color freehand brushes work on nearest-triangle mesh hits in the 3D viewport and directly in texture space in the UV viewport, with spline path strokes (23) and a multi-channel eyedropper (45); the Select tool builds polygon masks by face, connected element, or UV island. Projection (camera-view) painting, smudge, clone, and quick mask remain open. | Brush hit-testing and stroke recording live in `apps/substancecraft`/`crates/core`; camera-space projection painting is the main blocker shared with area 09. |
| 06 | Brush and stroke systems | Partial | Persistent interpolated UV strokes with Round, Square, Splatter, and bitmap-alpha tips; hardness, spacing, angle, follow-path rotation, seeded size/angle jitter and scatter, pen pressure driving radius and/or opacity, and lazy-mouse stabilization (08). Brush tips and sizes, bitmap alphas included, pin to a shelf saved in user preferences (QoL-08), and recent multi-channel brush materials restore in one click (QoL-09). Presets that bundle tip and material values together remain open. | Stroke math lives in `crates/core`; the shelf and recent list live in `apps/substancecraft/src/preferences.rs`, outside project data. |
| 07 | Symmetry | Partial | Mirror symmetry across an X, Y, or Z plane with an adjustable offset, toggled in the Tools drawer: each 3D brush hit is reflected and snapped to the closest surface point (so asymmetric meshes still get a sensible mirrored stroke), and the UV view mirrors across U = 0.5. Both strokes of a drag undo as one batch edit and paint every enabled channel. Radial symmetry repeats a stroke 3, 4, 6, 8, or 12 times around the chosen axis through the object origin, each copy snapped to the surface and undone with the original. Radial copies apply in the 3D view only; a live mirrored-cursor preview remains open. | Mirror and radial math are in `crates/core/src/painting.rs`; every copy is its own stroke path, so seam splitting works per copy. |
| 08 | Stroke assistance and precision | Partial | In the Tools drawer: lazy-mouse stabilization (the brush trails the cursor on an adjustable radius), Shift-click straight lines from the last dab sampled in screen space and projected onto the surface, and seam-aware painting that restarts a stroke when it crosses into another UV island instead of streaking across UV space. Surface-aligned stamping and a brush-size cursor preview remain open. | Lazy-mouse stabilizer (QoL-06) now feeds the main stroke; surface-aligned stamping would reuse the same hit-point normal already computed per dab. |
| 09 | Projection systems | Partial | Fill textures and bitmap masks project through UV, triplanar, planar, cylindrical, spherical, and decal modes (axis, scale, offset, rotation, and real-world tile size), all selectable in layer properties. Camera (view) projection painting remains open. | UV/triplanar/planar/etc. projection math is in `crates/core`; camera-space projection is the single largest remaining projection mode and the main blocker for several QoL/major items. |
| 10 | Fill layers | Partial | Fill layers write uniform values or per-channel bitmaps (Base Color, Roughness, Metallic, Height, Normal, Emissive, Opacity) through UV, triplanar, planar, cylindrical, spherical, or decal projection with scale, offset, rotation, blend sharpness, and optional real-world tile size, and composite through generator, painted, polygon, bitmap, anchor, and ID masks. Same-size UV textures are read texel for texel without resampling. Fill content from procedural (graph) materials remains open. | Fill evaluation is in `crates/core` compositing; procedural fill content depends on a graph/material-node system that does not exist yet. |
| 11 | Paint layers | Partial | Persistent multi-channel paint, erase, and ID strokes with visibility, opacity, filters, undo/redo, and CPU compositing. | CPU compositing path only; GPU compositing would be a Performance Features item. |
| 12 | Layer stack | Partial | Ordered paint and fill layers plus nestable groups (children composite first, then blend through the group's opacity, mask, filters, and blend mode), with add, delete, reorder, move into/out of groups, visibility, opacity, rename, channel toggles, and blend modes (Normal, Multiply, Screen, Overlay, Soft light, Darken, Lighten, Difference, Add, Subtract; W3C separable formulas, applied where the backdrop has coverage; normals always blend normally), all undoable. Groups can also pass through: their children blend straight onto the stack beneath, and the group's opacity, mask, and filters fade that result in. Per-channel blend modes remain open. | Group nesting and blend modes live in `crates/core`; pass-through is a group-only `BlendMode` variant (validation rejects it elsewhere), and flattening a pass-through group yields a Normal layer. |
| 13 | Layer flattening | Partial | "Flatten to bitmaps" bakes the selected layer or group, with its opacity, mask, and filters, into one straight-alpha PNG per channel it writes and inserts a fill layer using them that composites identically (texel-exact). The source is kept below, hidden, and the whole edit undoes in one step. Flattening several unrelated layers at once remains open. | Flatten bakes through the same compositing path as export, so it stays texel-exact with the existing flatten tests. |
| 14 | Masks | Partial | Mask = generator base, painted grayscale strokes over it, multiplied by an optional projected bitmap mask (invertible), then polygon (geometry) and ID-colour clipping, with polygon-mask inversion, a saved final-mask inversion control, and an ordered mask filter stack. UV-tile masks remain open. | Mask evaluation order is centralized in `crates/core::compositing`; UV-tile masks would need per-tile mask storage alongside per-tile strokes. |
| 15 | Smart Masks | Partial | Edge Wear and Dirt one-click layers pair a fill with a mesh-map-driven generator; saving reusable custom presets remains open. | Edge Wear/Dirt reuse the generator pipeline (16); custom presets need a serializable preset store similar to export presets. |
| 16 | Generators | Partial | Edge Wear (convex curvature), Dirt (AO + cavity), Orientation, Gradient, Noise, and Thickness (thin or thick parts from the baked thickness map) generators with seeded object-space breakup. An ID generator remains open. | Generator math is in `crates/core/src/generators.rs`; ID masks already exist as layer clipping, so an ID generator would mainly expose them as a generator. |
| 17 | Texture generators and procedural resources | Partial | Deterministic seeded 3D gradient noise and fBm (seamless across UV seams); patterns, grunges, and alphas remain open. | Noise/fBm are deterministic and seeded for reproducible bakes; patterns/grunges would be new bitmap-based generator types. |
| 18 | Filters and adjustment effects | Partial | Blur, Sharpen (unsharp mask), Levels, Invert, and Hue/Saturation filters apply as ordered, undoable stacks to a layer's content or its mask, on the deterministic CPU path; blur radii scale with texture resolution. Additional filters and per-channel filter scoping remain open. | Filter stack runs on the CPU deterministic path; a GPU filter path would be a Performance Features item. |
| 19 | Anchor Points | Partial | Layer properties offer an anchor mask: read a channel (luminance for colours) of the stack as composited up to and including an earlier layer, with low/high remap and invert. The link is by layer id, so it survives reordering and renaming; anchors to later layers, the layer itself, or an ancestor are rejected by validation and the bake. Anchoring to individual effects within a layer remains open. | Anchor validation guards against cycles/self-reference at both edit time and bake time. |
| 20 | Smart Materials | Partial | Smart materials are serializable layer trees with named exposed parameters (fill colour, roughness, metallic, height, opacity, generator amount) and computed map requirements. From layer actions, any layer or group can be saved to the project or exported as a versioned `.scsmart` file, and smart materials insert from the project, the two built-ins (worn painted steel, rusty iron), or a file, with fresh layer ids and internal anchors relinked. A thumbnail browser and parameter panel for inserted instances remain open. | `.scsmart` files round-trip through the same layer-tree serialization as projects; a thumbnail browser needs an offscreen-render pipeline. |
| 21 | Materials and Substance resources | Partial | Material resources are reusable fill presets (values, channel bitmaps, projection, physical tile size) with provenance and tags. Layer actions apply one of ten original built-in PBR materials or a project material to a layer, and save a layer's fill as a new material. Procedural (graph-based) material resources remain open. | Built-in materials are static fill presets; procedural materials depend on the same graph/material-node system noted in area 10. |
| 22 | Decals, atlases, and surface details | Partial | Decal projection places a bitmap in an object-space box that conforms to the surface through baked positions and normals, fades on surfaces turning away, and clips every channel of its fill or mask outside the box. "Place on surface" centres it on the next clicked point facing out of that face; width, height, depth, and a 2 x 2 atlas cell are set in layer properties. A drag gizmo for moving and rotating decals remains open. | Decal clipping and surface conforming are in `crates/core`; a drag gizmo is an `apps/substancecraft` viewport-interaction addition only. |
| 23 | Spline and path-based details | Partial | "Draw path" in the Tools drawer places control points by clicking the mesh; Enter or Finish commits a Catmull-Rom stroke (open, or closed with Close loop) that keeps its control points, and Esc cancels. Brush spacing with bitmap tips repeats details along the path; erase mode erases along it. Paths are in UV space, so a path does not yet follow the surface across UV seams; path-driven blur remains open. | Paths are stored and evaluated in UV space; surface-following paths across seams need the same island-aware logic as seam-aware painting (08). |
| 24 | Vector graphics and text | Partial | SVG files import as resources and rasterise on load (via resvg); "New text resource" writes a `.sctext` file (text, size, optional font) rendered with the bundled Ubuntu Font Licence typeface, editable from the Assets drawer. Both work as fills, masks, brush alphas, and decals and reload when their files change. SVG `<text>` elements are not supported. | SVG rasterization uses `resvg`; `<text>` elements would need a second rasterization path or an SVG text-to-path preprocessor. |
| 25 | Baking Mode | Partial | Bake drawer with resolution, AO samples/distance, edge width/angle, cage distance, padding, an optional high-poly source, background baking with progress and cancel, ray-miss diagnostics, per-map preview, and TGA export. A bake log records each run's start time, settings, duration, and outcome (finished with ray-miss share, outdated, cancelled, or failed) and copies as text. The log lasts for the session and is not saved with the project. | Bake orchestration lives in `crates/core`; the log is app state in `apps/substancecraft/src/bake_log.rs`, bounded to 64 entries. |
| 26 | Mesh-map baking | Partial | Tangent-space normal, world normal, position, curvature, BVH-raycast AO, and thickness, baked from the working mesh or high-to-low from a merged high-poly FBX via cage rays (misses fall back to the low surface and are reported). Tangent frames are shared with the renderer. Per-mesh cage editing and name-matched bakes remain open. | BVH raycasting is CPU-only today; GPU raycast is a Performance Features item. Per-mesh cage editing needs a cage-mesh data model. |
| 27 | Skew correction and baking correction | Partial | With a high-poly source, the Bake drawer offers skew correction (cage rays bend from the smoothed normal toward the face normal), an edge guard angle that keeps bevels smooth, and an optional skew map bitmap scaling it per texel. The applied skew is baked into an inspectable Skew mesh map. Painting the skew map inside the app (rather than in an image editor, with auto-reload) remains open. | Skew map is an inspectable bake output already; in-app painting of it would reuse the existing paint-layer pipeline targeted at a mesh map instead of a channel. |
| 28 | Automatic rebaking and baking iteration | Partial | Mesh maps are keyed to the mesh revision and rebake automatically in the background when a generator or map preview needs them after mesh, scale, or smoothing changes. | `BakeKey` (QoL-18) now tracks every invalidation source; this is the dependency most other staleness-aware features build on. |
| 29 | UV Tile and UDIM workflows | Partial | UDIM tiles are detected from mesh UVs (`1001 + u + 10 v`); strokes may lie in any tile; "UDIM tiles…" exports the chosen preset once per tile (shifting mesh UVs and strokes onto the unit square, baking mesh maps per tile when needed) with a `$udim` name token or a `.1001` suffix, and the CLI does the same with `--udim`. Viewport display and painting of tiles beyond 1001, and per-tile caching, remain open. | UDIM detection and export are in `crates/core`/`crates/cli`; per-tile caching would reuse `BakeKey` scoped per tile. |
| 30 | 2D and 3D viewports | Partial | Filament 3D viewport with full-material and single-channel/mesh-map previews, live background re-baking while painting, and picking for paint and selection; a 2D UV viewport (Model, Split, or UV layouts) shows the selected texture set over its UV wireframe on a checkerboard, with zoom, pan, and texture-space painting. Viewport-only solo (layer, group, set), mask view, mask debug overlay, and UV seam / hard edge / tangent split overlays are available (QoL-03, 10, 11, 15). UDIM tile display remains open. | Viewport rendering is `crates/filament`; UDIM tile display needs per-tile texture binding in the same renderer. |
| 31 | Real-time PBR viewport | Partial | Filament metal/rough shading from baked Base Color, packed ORM (mesh-map AO, roughness, metallic), tangent-space normal, and emissive maps with smoothed tangent frames and alpha-tested opacity; image-based lighting environments and global illumination remain open. | Shading is a single built-in Filament material; IBL (see HDRI/IBL under Performance Features) is the main blocker for visual fidelity parity. |
| 32 | Rendering | Partial | The Light drawer renders the current material with the viewport camera and lighting to a 1K or 2K sRGB PNG through Filament, keeping the viewport framing at any output size, from the viewport or from any saved project camera (QoL-14). Lighting rigs, turntables, and colour-managed (OCIO) output transforms remain open. | Render path reuses the viewport's Filament scene; turntables/rigs mainly need camera/light keyframing, not new rendering code. |
| 33 | Shader system | Partial | One built-in metallic/roughness viewport material with material and flat-preview modes; extensible shader definitions remain open. | Only one shader is wired through `crates/filament`; extensible shaders need a shader-definition format the UI can list and swap. |
| 34 | OpenPBR support | Partial | "OpenPBR…" exports a texture set as per-input textures plus a MaterialX 1.39 document with an `open_pbr_surface` (base_color, specular_roughness, base_metalness, geometry_normal through a normalmap node, emission_color, geometry_opacity) and colour-space tags; a reader follows shader inputs back to their files, tested by round trip. Importing OpenPBR materials as layers remains open. | Round-trip tested via export-then-reparse; importing OpenPBR as layers needs a MaterialX-to-layer-tree mapping. |
| 35 | Color management | Partial | Bitmaps carry a colour-space tag (sRGB, linear sRGB, ACEScg, or raw data), set per bitmap in the Assets drawer. Colour channels convert tagged images to their sRGB encoding with the standard sRGB transfer curve and Bradford-adapted AP1/Rec.709 matrices; data channels read values raw. OCIO configs, viewport display transforms, and output transforms remain open. | Colour-space conversion is CPU math in `crates/core`; OCIO would be an external dependency decision, not a pure code change. |
| 36 | Asset management | Partial | Bitmaps, materials, smart materials, and export presets from the project and the built-in library form one typed index with provenance (author, licence, origin) and tags, searchable from the Assets drawer by multi-term queries over name, kind, tags, author, and licence; bitmap provenance and tags are edited there. Moved or renamed files relink by name (PROD-02). A shared on-disk library outside projects remains open. | Asset index and search are in-memory over project + bundled library resources; a shared on-disk library needs a filesystem-backed index outside any single project. |
| 37 | Supported resource categories | Partial | Bitmaps, SVGs, and text resources serve as fill textures, masks, brush alphas, and decals; material resources and smart materials are user-facing library entries; export presets are assets. Filters, generators, and environments as library resources remain open. | Resource kinds are closed enums today; new kinds (filters, generators, environments as resources) need a `Resource` variant plus UI support each. |
| 38 | Texture importing | Partial | PNG, JPEG, TGA, and SVG files (and `.sctext` text resources) import as project bitmap resources (straight-alpha RGBA8, bounded to 8192 px edges and 256 MiB files) with bilinear sampling, and reload automatically when edited outside the app (QoL-01). Each resource carries a colour-space tag, set in the Assets drawer, that bake inputs convert by; image sequences and environment maps remain open. | Import validation (size/file-size bounds) and decode live in `crates/core`; image sequences/environment maps are new resource kinds, not just new decoders. |
| 39 | Texture exporting | Implemented | Base Color, Roughness, Metallic, Height, Normal, Emissive, Opacity, ID, every mesh map, and any export preset's file set export as PNG, TGA, or OpenEXR, written as Gray, RGB, or RGBA to match each output's layout, per texture set or per UDIM tile (29), for one set or all sets at once (03). PNG outputs can be 16-bit; EXR stores half floats (ZIP-compressed) with sRGB colour decoded to linear and gray outputs as one `Y` channel. 16-bit and EXR samples come from the unquantized composite, so they keep detail 8-bit rounds away (TC-0261, TC-0262). | Writers are in `crates/api/src/textures.rs` (EXR through the `exr` crate); the bake carries RGBA16 samples only for outputs that need them, so 8-bit exports are unchanged. |
| 40 | Export presets and channel packing | Implemented | Serializable export presets route material channels, mesh maps, or spec/gloss conversions into each output channel with component selection, inversion, constants, Gray/RGB/RGBA layouts, `$textureSet` and `$udim` file naming, and skip-if-black. Each output can fix its own file format and bit depth, and a preset can cap the set size it accepts. Built-in Metal/Rough (ORM), Unreal Engine, Unity (URP Lit), Godot 4, glTF 2.0, Specular/Glossiness, and Separate channels presets ship; custom presets are validated, saved in the project, and edited in the desktop export panel (duplicate, edit, delete), and preset edits undo and redo. Texture sets can each keep their own preset and format. Masks are composited once per export, and every export passes a preflight check first (QoL-16). | Preset evaluation and preflight (QoL-16) share one code path so every export, including CLI, gets the same checks; `ExportPreset::resolved` settles each output's format against the export's choice. |
| 41 | Pipeline-targeted exporting | Implemented | Built-in Unreal Engine (DirectX normal, `T_` naming, packed ORM), Unity URP Lit (metallic + smoothness in alpha, separate occlusion), Godot 4 (ORM, OpenGL normal, height), glTF 2.0 metallic-roughness, and Specular/Glossiness (diffuse and specular mixed from Base Color and Metallic in linear light) texture presets with tested routing; glTF 2.0 scenes with metallic-roughness materials and OpenPBR MaterialX documents for renderers (34, 50); headless, deterministic CLI exports for build pipelines (49); and an engine-side import guide (`docs/engine-import.md`) giving each file's colour space and import settings. | Engine presets are data, not special-cased code; spec/gloss conversion is an export source (`SpecGlossMap`), so custom presets can use it too. |
| 42 | History and nondestructive editing | Implemented | Bounded undo/redo (Ctrl+Z / Ctrl+Shift+Z) covers strokes, layer settings (fill, generator, polygon and bitmap masks, filters, opacity, visibility, channels), layer and group insert/remove/move, bitmap relinks, texture-set properties (resolution, height force, saved export choice), whole texture sets, export presets, and mesh edits (primitive, import scale, smoothing with its polygon-mask remap, high-poly source, replacement), reloading the mesh when undo changes it; slider drags are one step. An explicit save writes the history beside the project (`<project>.history`), and opening the unchanged file restores it (TC-0263, TC-0265). | The sidecar holds a hash of the saved project file and is ignored once the file changes, since commands only apply to the state they were recorded against; keeping it out of `.sproject` leaves project diffs clean (PROD-05). |
| 43 | Selection and isolation | Partial | Viewport picking selects faces, connected mesh elements, or UV islands into a layer polygon mask, with hover preview and Shift-click removal; viewport isolation (solo) is covered by QoL-03. | Selection reuses the same mesh-hit/UV-island logic as painting (05). |
| 44 | Interface customization | Partial | Dock-like panels, a UI scale preference (A11Y-01), and rebindable keyboard shortcuts with hold-to-override tools (QoL-07), saved in user preferences, are in place; saved panel layouts remain open. | Preferences live in `apps/substancecraft/src/preferences.rs`; saved layouts would add panel geometry to the same file. |
| 45 | Color selection | Partial | "Pick material" in the Tools drawer arms an eyedropper: the next click on the mesh copies Base Color, roughness, metallic, opacity, and emission from the baked material into the brush. Recent brush materials sit in a history bar (QoL-09). A colour-managed picker (beyond sRGB) remains open. | Eyedropper reads the already-baked material, so it reflects composited results, not just the top layer. |
| 46 | Display and diagnostics | Partial | Channel selector, mesh-map previews, stale-bake reasons, the surface-to-layer inspector (QoL-02), mask view and mask overlay (QoL-10, 11), edge overlays (QoL-15), bake log (25), and cache usage (PROD-06) exist. A dedicated diagnostics panel collecting them remains open. | Inspection runs the same compositor with a one-texel probe (`crates/core/src/inspect.rs`), so it cannot drift from bakes. |
| 47 | Physical size | Partial | Object-space projections take an optional real-world tile size in scene units (metres after import scale), toggled as "Real size" in layer properties, so a texture keeps its physical size whatever the mesh bounds; material resources carry it. Physical scale for generators and noise remains open. | Real-world tile size is stored per layer/material; generator physical scale needs the same unit conversion applied to noise/generator sampling. |
| 48 | Automation and scripting API | Partial | Public Rust API facade (including preset-driven export baking and writing) and read-only MCP tools for mesh and export presets; stable command coverage remains open. | Facade lives in `crates/api`; MCP tools in `crates/mcp` are currently read-only, so write-capable automation is the main gap. |
| 49 | VFX and production-pipeline support | Partial | `substancecraft-cli export <project> --out <dir> [--preset] [--format] [--udim] [--ao-samples]` runs headless, deterministic jobs (byte-identical output for the same inputs, verified by test): it restores the project mesh and high-poly source, bakes mesh maps where needed, runs preflight, and writes every texture set, with exit codes 0 / 1 / 2 for success, job failure, and bad arguments; `batch <jobs.txt> [--workers <n>]` runs a job list (PROD-04). UDIM and ACEScg tagging are covered above; OCIO and published release-compatibility targets remain open. | CLI determinism is verified by a byte-identical-output test; this is the primary foundation the Production Features category builds on. |
| 50 | Substance ecosystem integration | Partial | Interchange uses documented open standards: "glTF…" exports the mesh with one metallic-roughness material per slot (base colour, shared ORM for occlusion/metal/rough, normal, emissive, blend mode), verified by re-importing; OpenPBR in MaterialX is covered in 34. No proprietary formats are read or written. | Interchange is deliberately open-standards only (glTF, MaterialX); no proprietary Substance format reader/writer is planned. |

## QoL Features backlog

These features add little new capability, but they shorten everyday iteration. They come from a technical-art review of the current build. **High** items save hours per week on large projects and are scheduled ahead of the remaining production work (delivery stage 5); **Medium** and **Low** items are taken opportunistically. Each builds on the capability areas listed and follows the same status rules.

| ID | Feature | Builds on | Priority | Status | Acceptance target | Notes |
| --- | --- | --- | --- | --- | --- | --- |
| QoL-01 | Resource auto-reload | 36, 38 | High | Implemented | Watch referenced bitmap files; when one changes on disk, reload it and rebake only the texture sets that use it, with an optional confirm-before-reload mode. A missing or undecodable file keeps the last good pixels and reports the error. Files are polled once a second (modification time and size), which also catches save-by-rename; the Assets drawer offers Auto, Ask (Reload/Ignore prompt), and Off. | Polling (1s) keeps this dependency-free; a filesystem-watcher backend would reduce latency but adds a platform-specific dependency. |
| QoL-02 | Surface-to-layer inspector | 12, 43 | High | Implemented | Clicking the model lists, top to bottom, the visible layers and groups that contribute at that texel for the active channel, with each one's effective mask value and the generator or mesh map driving it; choosing an entry selects that layer. "Inspect texel" in the Tools drawer (View mode) arms the click; each row shows coverage × opacity × mask and names its mask drivers. | The inspector runs the real compositor with a one-texel probe, so its numbers match bakes; one click costs one channel composite. |
| QoL-03 | Solo and isolation | 12, 43, 46 | High | Implemented | One action solos a channel, layer, group, mask, generator, or texture set in the viewport without changing project data; solo state is never saved or exported. Solo chips in the Tools drawer pick All, Layer, Mask, Generator, Overlay, or Set; channels solo through the existing channel preview. | Solo bakes a hidden-others copy of the set for the preview only; a test checks the project is unchanged. Anchor masks of a soloed layer read the soloed stack. |

## Delivery order

1. **Foundation and automation:** project schema, mesh/pose data, command API, MCP tools, tests, and clean-room CI.
2. **Mesh-to-preview loop:** robust FBX and glTF import, UV/material sets, actual 3D viewport, camera controls, and channel inspection.
3. **First texturing loop:** UV paint, texture tiles, layer data, deterministic composition, undo/redo, and PNG export.
4. **Material authoring:** multi-channel brushes, masks, fill layers, filters, and export profiles.
5. **Workflow acceleration:** the High-priority QoL backlog items: resource auto-reload, surface-to-layer inspector, solo and isolation, material instances, export preflight, stale bake detection, and smart import assignment.
6. **Production workflows:** skeletal animation pose selection, projection, baking, generators, UDIMs, and higher-resolution performance; the High-priority Production Features backlog items (autosave/recovery, batch/headless jobs) land alongside this stage.
7. **Extensibility:** versioned public API, MCP resources/prompts/tools, scripting, plugins, and pipeline integrations; plugin/extensibility infrastructure (Production Features) and large-project/GPU performance work (Performance Features) land here.
8. **Reach:** Accessibility Features (UI scaling, configurable input, colour-vision modes) and any remaining Medium/Low items across all four backlogs, taken opportunistically.

Feature completion is judged by observable behavior and acceptance tests, not by menu presence. Asset libraries, shaders, and reference data must be original or redistributable under an explicit license.
