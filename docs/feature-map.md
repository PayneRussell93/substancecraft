# SubstanceCraft Feature Map

This is the product capability map derived from the supplied Painter feature inventory. It is a clean-room implementation plan, not a claim of parity. Status is conservative: **Partial** means a tested slice or relevant foundation exists but the acceptance target is incomplete; **Planned** means no implementation of the target exists yet.

## Status key

- **Implemented:** the acceptance target is met and covered by automated tests. A capability area is Implemented once nothing in its row remains open.
- **Partial:** some acceptance criteria are met, or a tested foundation exists, but meaningful work remains.
- **Planned:** no implementation of the acceptance target exists yet.

## Category taxonomy

Every row below (capability area or backlog item) belongs to one of five categories, and every table carries a **Notes** column with practical context (primary implementation crate, dependencies, or the main follow-up risk) that is not restated in the acceptance target:

| Category | Purpose | Examples |
| --- | --- | --- |
| **Features** | What SubstanceCraft can do | Painting, layers, baking, UDIMs |
| **QoL Features** | Make existing workflows faster or easier | Solo mode, layer search, lazy-mouse stabilization |
| **Production Features** | Make it dependable in professional pipelines | Batch jobs, autosave/recovery, asset relinking, caching |
| **Performance Features** | Make the same workflows faster or larger | GPU baking, tiled processing, incremental recomposition |
| **Accessibility Features** | Make the application adaptable to more users | UI scaling, configurable input, colour-vision modes |

| 01 | Project and document management | Implemented | Versioned JSON project model, validation, atomic `.sproject` save/load, texture sets, named poses, bitmap resource references, and custom export presets are implemented, and the desktop app opens a `.sproject` passed as its first argument. Saves are stable, sorted, diff-friendly JSON (PROD-05); older schemas upgrade on load with a report (PROD-03, now schema 3); autosave and crash recovery (PROD-01) and relinking of moved files (PROD-02) are in place; named inspection cameras are saved with the project (QoL-14). Mesh and bitmap assets are external references, relinked when moved (PROD-02); "Replace mesh…" swaps the mesh and keeps every set and layer (42). Templates start new projects: five original built-ins (game asset, Unreal Engine, Unity URP, film/VFX with EXR and UDIM, worn metal prop) or a `.sctemplate` file saved from any texture set. A template carries resolution, channels, height strength, export choice, and starter layers, and the new project keeps the current mesh with one set per material slot, after a confirmation (TC-0303, TC-0304). | Schema and (de)serialization live in `crates/core`; the on-disk format and migration chain live in `crates/api/src/project_format.rs`, so each schema bump adds one upgrade step there. |
| 02 | Mesh importing and preparation | Implemented | Binary and ASCII FBX 7.4+ and glTF 2.0 (`.gltf` with external or embedded buffers, and `.glb`) meshes import through the API and desktop picker, as do STEP CAD files (`.step`/`.stp`, AP203/AP214/AP242): exact B-rep solids and surface models are tessellated to a chord tolerance of 0.05% of the model size (planes, cylinders, cones, spheres, tori, NURBS, extrusions, revolutions, and offsets), AP242 tessellated faces are read as they are, assemblies are flattened with every instance placed, lengths become metres, each surface colour becomes a material slot, and every face gets its own UV chart in a packed atlas per slot (TC-0339 to TC-0344); with native UVs or planar fallback. glTF flattens the default scene with node transforms applied and maps each material to a material slot; FBX maps its per-polygon material layer onto slots named after the model's connected materials (TC-0298), so both give one texture set per material. ASCII FBX imports exactly as the same binary file does (TC-0305, TC-0306). Auto-smoothed shading normals (angle threshold, welded across unshared FBX corners) and crease-aware Loop subdivision (0–3 levels, UV seams preserved) are implemented. Skeletal animation: skeletons, skin weights (up to four per vertex), and animation clips import from glTF skins and animations and from FBX skin clusters, bone hierarchies (full FBX pivots, offsets, pre- and post-rotations, and rotation orders), and animation stacks. The Poses drawer shows the bind pose, the rest pose, or a clip at any time, plays and loops clips (in place, or with root motion), and saved poses keep their frame. The viewport, picking, brush outline, and edge overlays follow the pose, while painting, bakes, and exports stay on the bind mesh, so strokes land in UV space on the posed surface (TC-0316 to TC-0322). | FBX/glTF parsing lives in `crates/api` (`fbx_rig.rs` for FBX rigs), normal/subdivision math and the rig model and linear-blend skinning (`rig.rs`) in `crates/core`. Rigs are read again with the mesh file, never saved in the project. The posed mesh is skinned before smoothing and subdivision, so it shares the bind mesh's topology and picks map straight back. FBX curves are interpolated linearly (tangents are not read), and morph targets are not imported. Verified on Unreal Engine 5 FBX characters. |
| 03 | Texture Sets | Implemented | Multi-material meshes get one texture set per material slot, each with its own layers, channels, and resolution (512 / 1K / 2K / 4K / 8K in the texture-set properties); unselected sets bake in the background so every slot shows its own material in the viewport. A set can remember its own export preset, file format, and UDIM choice ("This set" in the export panel), which "All sets…" and the command line follow unless told otherwise. Sets above 2048² bake in tiles (PERF-03); the viewport shows sets above 4K as a downscaled preview, while exports keep full size. | Background baking runs on a worker thread keyed by texture-set id. The preview copy scales stroke radii with the resolution (`TextureSet::downscaled`), so it looks like the full set filtered down. |
| 04 | Material channels | Implemented | Base Color (RGBA); Roughness, Metallic, Height, and Opacity (scalar); Emissive (sRGB); Normal (tangent-space vector); and baked Ambient Occlusion composite per layer with per-layer channel enablement and export. Height converts to normal detail (whiteout blend) with a per-texture-set strength. Up to eight user-defined channels per texture set (`User0` to `User7` in project files and presets) are added under User channels in the texture-set properties, each with a name, colour or grey data, and a default value. Layers enable them with the channel chips; fills and the brush write their values, and fills can take a bitmap per user channel; groups pass them through, flattening keeps them, the viewport previews them by name, and export presets and the export chips write them over their default. The automation API and MCP define and paint them too (TC-0358 to TC-0362). | `MaterialChannel::User(slot)` and `UserChannel` live in `crates/core`; user channels composite as straight-alpha colour and export as stored data (EXR does not decode them as sRGB). They are not part of the PBR viewport material, and material instances follow the master's user values without per-channel overrides; anchor masks can read them (19). |
| 05 | Painting tools | Implemented | Multi-channel paint, erase, grayscale-mask, and ID-color freehand brushes work on nearest-triangle mesh hits in the 3D viewport and directly in texture space in the UV viewport, with spline path strokes (23) and a multi-channel eyedropper (45); the Select tool builds polygon masks by face, connected element, or UV island. With Projection on (Tools drawer), paint, erase, and mask strokes are drawn on screen and projected onto the visible surface (09). In Paint mode the Tool chips switch the brush to Clone, which copies every enabled channel of the stack (the layers beneath, within the layer's group, with the layer's earlier strokes on top) from a source picked with Set source, the first stroke fixing the offset for the next ones; or to Smudge, which drags the stack along the stroke by up to Strength × the brush radius (TC-0354, TC-0355); or to Blur, which averages the stack under the stroke over Strength × the brush radius (TC-0370). Paint quick mask (T) paints a temporary mask over the tinted material, Paint to open and Erase to close, optionally inverted; Use records it as one undo step, and from then on paint and mask strokes on that set stay inside it until it is cleared (TC-0356, TC-0357). | Clone, smudge, and blur are a `StrokeSource` on paint strokes, sampled in texture space by the compositor (`crates/core/src/compositing.rs`): they never project, and the region halo grows by their reach so incremental and tiled bakes stay exact. Sets above 2048² bake in 2048-texel tiles, so a clone offset beyond about 990 texels there exceeds the tile budget and the bake reports it; untiled fallback for such offsets is a follow-up. A layer with them cannot be flattened on its own, since they read the layers beneath. Quick masks are `Stencil`s of the texture set that strokes name, and never change once used; the app side is `apps/substancecraft/src/stroke_tools.rs`. |
| 06 | Brush and stroke systems | Implemented | Persistent interpolated UV strokes with Round, Square, Splatter, Streak, Ring, Cloud, and bitmap-alpha tips; hardness, spacing, angle, follow-path rotation, seeded size/angle jitter and scatter, pen pressure driving radius and/or opacity, and lazy-mouse stabilization (08). Brush tips and sizes, bitmap alphas included, pin to a shelf saved in user preferences (QoL-08), and recent multi-channel brush materials restore in one click (QoL-09). Brush presets bundle tip, size, and every material channel: four original built-ins (chipped paint, rust spots, grime, gold leaf) and "+ Material" on the shelf, which pins the current brush as a preset (TC-0288). | Stroke math lives in `crates/core`; the shelf and recent list live in `apps/substancecraft/src/preferences.rs`, outside project data. |
| 07 | Symmetry | Implemented | Mirror symmetry across an X, Y, or Z plane with an adjustable offset, toggled in the Tools drawer: each 3D brush hit is reflected and snapped to the closest surface point (so asymmetric meshes still get a sensible mirrored stroke), and the UV view mirrors across U = 0.5. Both strokes of a drag undo as one batch edit and paint every enabled channel. Radial symmetry repeats a stroke 3, 4, 6, 8, or 12 times around the chosen axis through the object origin, each copy snapped to the surface and undone with the original. Radial copies apply in the 3D view only. While hovering, the brush cursor previews every copy: a fainter footprint outline on the surface wherever a mirrored or radial copy will paint (TC-0330). | Mirror and radial math are in `crates/core/src/painting.rs`; every copy is its own stroke path, so seam splitting works per copy. The preview and the stroke pick their copies through one function (`symmetry_copies`), so the cursor never shows a copy that would not paint. |
| 08 | Stroke assistance and precision | Implemented | In the Tools drawer: lazy-mouse stabilization (the brush trails the cursor on an adjustable radius), Shift-click straight lines from the last dab sampled in screen space and projected onto the surface, and seam-aware painting that restarts a stroke when it crosses into another UV island instead of streaking across UV space. The brush cursor outlines the true footprint on the surface: the brush's texel radius carried through the hovered triangle's UVs, so it stretches where the UVs do (TC-0301), or the screen-space radius when projecting (09). With Align to surface on, each 3D dab records a stamp frame from the hit triangle's UV layout, so stamps stay round and upright on the surface (x along the direction of increasing U) where the UVs stretch, shear, turn, or mirror; frames keep each stamp's texel area, and UVs stretched more than 8:1 stamp unaligned (TC-0352). Follow-path rotation follows the stroke's true heading, diagonals included (TC-0353). | Lazy-mouse stabilizer (QoL-06) feeds the main stroke. Stamp frames are per-point `StampFrame`s on strokes (`crates/core/src/brush.rs`), from `MeshGeometry::stamp_frame`; aligned strokes always place stamps rather than capsules. UV-view and projected strokes are never aligned. |
| 09 | Projection systems | Implemented | Fill textures and bitmap masks project through UV, triplanar, planar, cylindrical, spherical, and decal modes (axis, scale, offset, rotation, and real-world tile size), all selectable in layer properties. Camera (view) projection painting: with Projection on in the Tools drawer, paint, erase, and mask strokes keep the view they were drawn through, so their points and radius are in screen pixels. Each texel takes the brush coverage where its baked surface position lands on screen, if that surface faced the camera and was not hidden behind other geometry. Strokes therefore cross UV seams unbroken and keep their on-screen size. The brush cursor shows the true footprint; ID strokes, symmetry, and paths stay in UV space (TC-0272 to TC-0275). Projection painting pauses while an animated mesh is posed (02) and resumes in the bind pose. | Projection math is in `crates/core` (`camera_paint.rs` for strokes). A projected stroke rasterises its footprint and a depth buffer of the mesh in screen space, and finds candidate texels through cached per-block position bounds of the mesh maps, so it needs mesh maps (baked automatically) and costs one mesh rasterisation per stroke per bake. |
| 10 | Fill layers | Implemented | Fill layers write uniform values or per-channel bitmaps (Base Color, Roughness, Metallic, Height, Normal, Emissive, Opacity) through UV, triplanar, planar, cylindrical, spherical, or decal projection with scale, offset, rotation, blend sharpness, and optional real-world tile size, and composite through generator, painted, polygon, bitmap, anchor, and ID masks. Same-size UV textures are read texel for texel without resampling. Make procedural (layer properties) gives a fill a material graph: an ordered list of nodes (every mask generator but ID, mesh maps, UV, projected bitmaps, blend modes, arithmetic, every per-texel filter, colour ramps, and component splits), each reading earlier nodes or constants, and a node or constant per channel the layer writes; other channels keep the fill's value or bitmap (TC-0364, TC-0365, TC-0368). | Graphs are `MaterialGraph`s on the layer (`crates/core/src/graph.rs`), evaluated per texel in the CPU compositor, so region and tiled bakes stay exact with no halo; smart materials, undo, and flattening carry them with the layer. The editor is a node list (`apps/substancecraft/src/graph_editor.rs`), not a wired canvas. |
| 11 | Paint layers | Implemented | Persistent multi-channel paint, erase, and ID strokes with visibility, opacity, filters, undo/redo, and CPU compositing. | CPU compositing path only; GPU compositing is tracked as PERF-06. |
| 12 | Layer stack | Implemented | Ordered paint and fill layers plus nestable groups (children composite first, then blend through the group's opacity, mask, filters, and blend mode), with add, delete, reorder, move into/out of groups, visibility, opacity, rename, channel toggles, and blend modes (Normal, Multiply, Screen, Overlay, Soft light, Darken, Lighten, Difference, Add, Subtract; W3C separable formulas, applied where the backdrop has coverage; normals always blend normally), all undoable. Groups can also pass through: their children blend straight onto the stack beneath, and the group's opacity, mask, and filters fade that result in. "Blend per channel" overrides the layer's mode for Base Color, Roughness, Metallic, Height, Emissive, or Opacity (for example Multiply colour over Normal roughness); flattening keeps the channel modes (TC-0287). | Group nesting and blend modes live in `crates/core`; pass-through is a group-only `BlendMode` variant (validation rejects it elsewhere, including as a channel mode or with channel modes), and flattening a pass-through group yields a Normal layer. |
| 13 | Layer flattening | Implemented | "Flatten to bitmaps" bakes the selected layer or group, with its opacity, mask, and filters, into one straight-alpha PNG per channel it writes and inserts a fill layer using them that composites identically (texel-exact). The source is kept below, hidden, and the whole edit undoes in one step. Ctrl-clicking more layers, anywhere in the stack, flattens them together: each keeps its own opacity, mask, filters, and blend mode (not those of enclosing groups), the merged fill goes above the topmost, and every source is hidden in the same undo step. Adjacent Normal layers merge texel-exactly; layers that sat between merged ones end up beneath the result (TC-0328, TC-0329). | Flatten bakes through the same compositing path as export, so it stays texel-exact with the existing flatten tests. A merge composites the chosen layers as a temporary Normal group in place of the topmost (`TextureSet::flatten_layers`), so it reuses single-layer flattening unchanged. |
| 14 | Masks | Implemented | Mask = generator base, painted grayscale strokes over it, multiplied by an optional projected bitmap mask (invertible), then polygon (geometry) and ID-colour clipping, with polygon-mask inversion, a saved final-mask inversion control, and an ordered mask filter stack. UV-tile masks limit a layer or group to chosen UDIM tiles ("UV tiles" in layer properties, when the mesh spans several); the plain bake is tile 1001, and each tile's export hides the layers limited to other tiles (TC-0297). | Mask evaluation order is centralized in `crates/core::compositing`; tile masks are a layer setting checked through `MaterialLayer::shown`, and `TextureSet::shifted_to_tile` applies them per tile. |
| 15 | Smart Masks | Implemented | Edge Wear and Dirt one-click layers pair a fill with a mesh-map-driven generator. A smart mask is a reusable mask setup: a layer's generator, bitmap mask, mask filters, and final inversion. "Smart mask" in layer properties applies one of five original built-ins (worn edges, cavity dirt, dust from above, thin parts, blotches) or a project mask, and saves the layer's own setup to the project. Painted mask strokes, polygon selections, and ID clipping stay with the layer. Saving and deleting are undoable, masks save with the project and are searchable in the Assets drawer (TC-0278, TC-0279). | Smart masks live in `crates/core/src/library.rs` beside materials and smart materials, and apply through the layer-settings history like any inspector edit. |
| 16 | Generators | Implemented | Edge Wear (convex curvature), Dirt (AO + cavity), Orientation, Gradient, Noise, and Thickness (thin or thick parts from the baked thickness map) generators with seeded object-space breakup, a Pattern generator (17), and an ID generator that selects the texture set's painted ID map by colour with a tolerance and soft edge. Its colour can be picked from the model, and it needs no mesh maps (TC-0276, TC-0277). | Generator math is in `crates/core/src/generators.rs`. The ID generator reads the same ID map as ID clipping, per texel, so incremental and tiled bakes stay exact; unlike the clip, it is the mask's base, so strokes, bitmaps, and filters refine it. |
| 17 | Texture generators and procedural resources | Implemented | Deterministic seeded 3D gradient noise and fBm (seamless across UV seams). The Pattern generator draws stripes, checker, dots, scratches, and ridged grunge in object space, so it never seams, with axis, width, softness, seed, and a mesh-relative or real-world size. Three procedural brush alphas join the tips: Streak (tapered scratch line), Ring, and Cloud (TC-0290, TC-0291). | Noise/fBm are deterministic and seeded for reproducible bakes; patterns are analytic or noise-based functions of the object-space position (`generators.rs`), and alphas are stamp shapes in `brush.rs`, so neither needs bitmap files. |
| 18 | Filters and adjustment effects | Implemented | Blur, Sharpen (unsharp mask), Levels, Invert, Hue/Saturation, Brightness/Contrast, Posterize, Threshold, and a two-colour Gradient map apply as ordered, undoable stacks to a layer's content or its mask, on the deterministic CPU path; blur radii scale with texture resolution. A layer's content filters can be limited to chosen channels ("On channels"), for example blurring roughness while colour stays sharp (TC-0299, TC-0300). | Filter stack runs on the CPU deterministic path; a GPU filter path would be a Performance Features item. |
| 19 | Anchor Points | Implemented | Layer properties offer an anchor mask: read a channel (luminance for colours) of the stack as composited up to and including an earlier layer, with low/high remap and invert. The link is by layer id, so it survives reordering and renaming; anchors to later layers, the layer itself, or an ancestor are rejected by validation and the bake. Read at (layer properties) anchors to one effect within the layer instead of the whole layer: its fill alone, its fill and strokes, or the stack through any one of its content filters. User channels can be read too (TC-0363). | Anchor validation guards against cycles/self-reference at both edit time and bake time. An effect is stored on the anchor (`AnchorEffect`) and read by leaving the later effects out of the truncated stack; if the anchor layer later loses that effect (a filter removed), the anchor reads the nearest stage that remains instead of failing the bake. |
| 20 | Smart Materials | Implemented | Smart materials are serializable layer trees with named exposed parameters (fill colour, roughness, metallic, height, opacity, generator amount) and computed map requirements. From layer actions, any layer or group can be saved to the project or exported as a versioned `.scsmart` file, and smart materials insert from the project, the two built-ins (worn painted steel, rusty iron), or a file, with fresh layer ids and internal anchors relinked. Inserted smart materials keep their evolution controls (QoL-20) as live sliders. Layer actions browse smart materials as thumbnails: each is baked onto a sphere and shaded on the CPU, and clicking one inserts it. An inserted instance keeps its exposed parameters, and its layer properties show a "Parameters" panel with a slider or colour button for each one; each change edits the layer it drives, and a drag is one undo step. Saving the instance again keeps the same parameters (TC-0337, TC-0338). | `.scsmart` files round-trip through the same layer-tree serialization as projects. Thumbnails come from `ThumbnailStage` (`crates/core/src/thumbnails.rs`), which bakes the sphere's mesh maps once at 64² so generators show. The browser caches each thumbnail by a hash of its layer tree and renders at most one new thumbnail per frame. Parameters live on the instance's root layer (`MaterialLayer::exposed`), with ids remapped on insertion. |
| 21 | Materials and Substance resources | Implemented | Material resources are reusable fill presets (values, channel bitmaps, projection, physical tile size) with provenance and tags. Layer actions apply one of ten original built-in PBR materials, two original built-in procedural materials (Rust and Painted stripes), or a project material to a layer as a copy, save a layer's fill (and graph) as a new material, or link the layer to a project material as an instance (QoL-05); project materials, procedural ones included, are edited in the Assets drawer. A procedural material carries its graph (10) to every layer it is applied to; instances follow the master's graph, except for channels whose value they override (TC-0366, TC-0367). | Procedural materials are material resources with a `MaterialGraph`. Graphs are original and native; Substance (`.sbsar`) graphs are not read. |
| 22 | Decals, atlases, and surface details | Implemented | Decal projection places a bitmap in an object-space box that conforms to the surface through baked positions and normals, fades on surfaces turning away, and clips every channel of its fill or mask outside the box. "Place on surface" centres it on the next clicked point facing out of that face; centre, facing axis, spin, width, height, depth, and a 2 x 2 atlas cell are also set in layer properties, so decals place without the mouse (A11Y-04, TC-0295). "Move in viewport" turns on a drag gizmo, and the viewport outlines the decal with a tick towards its top edge. Dragging slides the decal along the surface under the pointer, facing out of each face and keeping its spin; Shift-drag spins it; Ctrl-drag resizes it within 0.01–4 units, keeping its proportions. Each drag is one undo step, and Esc turns the gizmo off (TC-0333, TC-0334). | Decal clipping and surface conforming are in `crates/core`; the drag maths are `DecalPlacement::move_to`, `scale_by`, and `corners`, and the gizmo is viewport interaction in `apps/substancecraft`. The gizmo pauses painting and camera orbiting while it is on. |
| 23 | Spline and path-based details | Implemented | "Draw path" in the Tools drawer places control points by clicking the mesh; Enter or Finish commits a Catmull-Rom stroke (open, or closed with Close loop) that keeps its control points, and Esc cancels. Brush spacing with bitmap tips repeats details along the path; erase mode erases along it. Each control also keeps the surface point under it, so the path runs over the model: the curve is traced through those points, snapped onto the surface, and cut wherever it crosses into another UV island, giving one stroke per island (one undo step) that each run right up to the seam, so paths follow the surface across UV seams and around edges (TC-0369, TC-0163). The placement line is drawn along that surface curve and stays on the model as the camera moves. The Blur tool (Tools drawer) softens every enabled channel of the stack under the stroke over Strength × the brush radius; drawn along a path, it is path-driven blur (TC-0370). | Surface paths are `PathSpec::surface_runs` (`crates/core/src/painting.rs`): seam crossings are found by bisection and placed where the two faces' planes meet, so folds are not cut short. Blur is a `StrokeSource` like clone and smudge, sampled in texture space by the compositor (a 25-tap disc). |
| 24 | Vector graphics and text | Implemented | SVG files import as resources and rasterise on load (via resvg); "New text resource" writes a `.sctext` file (text, size, optional font) rendered with the bundled Ubuntu Font Licence typeface, editable from the Assets drawer. Both work as fills, masks, brush alphas, and decals and reload when their files change. SVG `<text>` (with spans, anchoring, and per-span fills) is set in the bundled fonts: Ubuntu Light for every family, Hack for `monospace` (TC-0327). | SVG rasterization uses `resvg` with its `text` feature. System fonts are never read, so a family the bundle lacks falls back to Ubuntu Light and an SVG rasterises identically on every machine; fonts embedded by path are not loaded. |
| 25 | Baking Mode | Implemented | Bake drawer with resolution, AO samples/distance, edge width/angle, cage distance, padding, an optional high-poly source, background baking with progress and cancel, ray-miss diagnostics, per-map preview, and TGA export. A bake log records each run's start time, settings, duration, and outcome (finished with ray-miss share, outdated, cancelled, or failed) and copies as text. The log is saved beside the project (`name.sproject.bakelog`) and comes back when the project is opened; clearing it removes the file, and a damaged one reads as empty (TC-0251, TC-0371). | Bake orchestration lives in `crates/core`; the log is app state in `apps/substancecraft/src/bake_log.rs`, bounded to 64 entries and saved as versioned JSON alongside the undo-history sidecar. |
| 26 | Mesh-map baking | Implemented | Tangent-space normal, world normal, position, curvature, BVH-raycast AO, and thickness, baked from the working mesh or high-to-low from a merged high-poly FBX via cage rays (misses fall back to the low surface and are reported). Tangent frames are shared with the renderer. High-to-low options are saved with the mesh and undoable: Match by name pairs each low part (material slot, or the mesh itself) with the high-poly meshes of the same name, ignoring case and `_low`/`_high`-style suffixes, and lists parts without a match (they use the whole high mesh); a cage mesh (the low mesh pushed out, same vertices) sets each ray's start and reach instead of Cage distance, and is refused when it does not match; without a cage, each part can scale the cage distance (×0.1 to ×10) (TC-0375, TC-0376). | BVH raycasting is CPU-only today; GPU raycast is a Performance Features item. Cage bakes are `bake_mesh_maps_caged` in `crates/core/src/mesh_maps.rs`; the cage is smoothed like the low mesh so they still pair, and is relinked by name when the project moves. |
| 27 | Skew correction and baking correction | Implemented | With a high-poly source, the Bake drawer offers skew correction (cage rays bend from the smoothed normal toward the face normal), an edge guard angle that keeps bevels smooth, and an optional skew map scaling it per texel: a bitmap, or one painted in the app with Paint skew map, which paints on the model or the UV view over the tinted material (Paint applies skew, Erase removes it) and on Done is saved with the mesh as one undoable edit, replacing the bitmap. The applied skew is baked into an inspectable Skew mesh map (TC-0171, TC-0377). | The painted skew map borrows the quick-mask painting path (`apps/substancecraft/src/stroke_tools.rs`) and is rasterised at map resolution on the bake thread (`HighToLowOptions::skew_image`). Its strokes stay in texture space, since projected strokes would need the very maps being baked. |
| 28 | Automatic rebaking and baking iteration | Implemented | Mesh maps are keyed to the mesh revision and rebake automatically in the background when a generator or map preview needs them after mesh, scale, smoothing, high-to-low option, or skew-map changes. The high-poly source is watched like bitmaps (Auto, Ask, or Off): re-exporting it from a modelling tool reloads it and starts a rebake, or waits in the reload prompt; a file caught mid-export keeps the previous high poly and says why (TC-0372). | `BakeKey` (QoL-18) tracks every invalidation source; the high-poly watch is `apps/substancecraft/src/resource_watch.rs`, polled with the bitmaps. |
| 29 | UV Tile and UDIM workflows | Implemented | UDIM tiles are detected from mesh UVs (`1001 + u + 10 v`); strokes may lie in any tile; "UDIM tiles…" exports the chosen preset once per tile (shifting mesh UVs and strokes onto the unit square, baking mesh maps per tile when needed) with a `$udim` name token or a `.1001` suffix, and the CLI does the same with `--udim`. The 3D and UV viewports show and paint every tile the mesh uses (30), and previews bake per tile with a per-tile cache: a tile is rebaked only when the strokes that can reach it, the mesh, its maps, or its bitmaps change, so painting one tile leaves the others cached; tile mesh maps beyond 1001 are baked once per bake key (TC-0170, TC-0373, TC-0374). | A tile's cache key hashes `TextureSet::for_tile` (the set shifted to the tile, without strokes that cannot reach it) with the mesh revision, bake key, and bitmap identities (`apps/substancecraft/src/udim_view.rs`). Incremental region patching is skipped on UDIM meshes; whole tiles rebake instead. |

## Delivery order

1. **Foundation and automation:** project schema, mesh/pose data, command API, MCP tools, tests, and clean-room CI.
2. **Mesh-to-preview loop:** robust FBX and glTF import, UV/material sets, actual 3D viewport, camera controls, and channel inspection.
3. **First texturing loop:** UV paint, texture tiles, layer data, deterministic composition, undo/redo, and PNG export.
4. **Material authoring:** multi-channel brushes, masks, fill layers, filters, and export profiles.
5. **Workflow acceleration:** the High-priority QoL backlog items: resource auto-reload, surface-to-layer inspector, solo and isolation, material instances, export preflight, stale bake detection, and smart import assignment. Complete.
6. **Production workflows:** skeletal animation pose selection, projection, baking, generators, UDIMs, and higher-resolution performance; the High-priority Production Features backlog items (autosave/recovery, batch/headless jobs) land alongside this stage.
7. **Extensibility:** versioned public API, MCP resources/prompts/tools, scripting, plugins, and pipeline integrations; plugin/extensibility infrastructure (Production Features) and large-project/GPU performance work (Performance Features) land here.
8. **Reach:** Accessibility Features (UI scaling, configurable input, colour-vision modes) and any remaining Medium/Low items across all four backlogs, taken opportunistically.

Feature completion is judged by observable behavior and acceptance tests, not by menu presence. Asset libraries, shaders, and reference data must be original or redistributable under an explicit license.
